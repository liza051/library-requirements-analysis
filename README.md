# Library Requirements Analysis

## About the Project

This project focuses on requirements analysis for a Library Reservation System.

The goal is to describe how readers and librarians interact with the library system using use cases, scenarios, and functional and non-functional requirements.

## Project Scope

The project covers:
- Identification of actors and their goals.
- Use Case diagram.
- Gherkin scenarios for one selected use case.
- Functional requirements written in EARS format.
- Non-functional requirements (NFR).
- Requirements traceability matrix.
- Requirements audit and architectural decisions.

## Connection to Previous Work

This project continues the Library Reservation System data modeling work developed in Laboratory Assignment 1.

The requirements must remain consistent with the previously created Entity-Relationship model.

## Documentation Structure

- `spec.md` — project intent, actors, use cases, and acceptance criteria.
- `use-cases/` — Use Case diagram.
- `scenarios/` — Gherkin scenarios.
- `requirements/` — EARS and non-functional requirements.
- `traceability/` — requirements traceability matrix.
- `audit/` — requirements audit.
- `adr/` — architectural decision records.
- `ai/` — AI prompts, responses, and feedback.
- `DEFENSE.md` — project defense and verification results.

## Modeling Approach

The project uses Use Case modeling, Gherkin scenarios, EARS requirements, and a traceability matrix to describe and verify system requirements.
